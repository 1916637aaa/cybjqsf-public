## 这是什么

「创游编辑器」官方服务器停服后，我按公开协议与抓包记录，用 Python 重写了一套**自用服务端**，并整理了部署、接入和运维文档。本仓库是这套服务端的学习记录，供同样在做停服软件研究的人参考。

**它不是**游戏本体、不是客户端安装包，也不提供任何可直接游玩的成品。

## 仓库里有什么

| 目录 | 内容 |
| :--- | :--- |
| `server/` | 服务端实现：HTTP 后端、WebSocket 服务、后台管理、代理、DNS/DoT，共 6 个服务 |
| `server/data/` | 协议定义、指令规格、数据 schema、干净初始库 |
| `server/scripts/` | 安装、证书生成、后台初始化、启停与自检脚本 |

| `conf/` | 统一配置模板（填一个服务器 IP 即可） |
| `scripts/` | IP 同步脚本 |
| `client/tools/` | 客户端研究工具：解包、参数化重打包、签名、校验（**需自备原版安装包**） |

## 仓库里刻意不放什么

| 内容 | 原因 |
| :--- | :--- |
| 原版客户端安装包（APK） | 属第三方版权二进制，不在本仓库分发 |
| 解密后的客户端源码与资源 | 逆向产出的专有代码与素材，不在本仓库分发 |

因此：**服务端可以完整跑起来；客户端部分需要你自己持有原版安装包**，再用 `client/tools/` 里的脚本在本地修改。没有原包时，客户端那一步无法完成——这是本仓库的能力边界，不是配置问题。

## 服务端怎么跑

```bash
# 0) 填 IP —— 唯一必填
vi conf/revive.env          # YOUR_SERVER_IP=<你的服务器公网IP>
bash scripts/sync_ip.sh

# 1) 部署到固定路径 /opt/privsrv
sudo mkdir -p /opt/privsrv && sudo cp -a server/. /opt/privsrv/
cd /opt/privsrv && sudo bash scripts/install.sh && bash scripts/check.sh
```

装完后：手机 WiFi 代理填 `<你的IP>:8080`（或用私人 DNS），并信任现场生成的根证书；后台管理在 `https://<你的IP>:38443`，密码见 `admin_password.txt`。

细节见 `docs/00_AI复活交接手册.md` 与 `server/docs/开服教程.md`。

## 环境要求

Linux（Ubuntu 20.04+ / Debian 11+ / CentOS 8+）、root、Python 3.8+、Node.js、nginx、openssl。
Python 依赖见 `server/requirements.txt`，`lz4js` 已内置，无需 npm install。

## 已知限制

- 服务端按协议重写，部分功能为占位或简化实现，不保证与官方行为完全一致
- 客户端改包依赖固定的原版版本（v0.8.10），版本不符时锚点校验会失败
- nginx 是部署最大变量：目标机若已有站点或走四层 SNI，需要先合并配置
- 没有真机就无法验证客户端能否登录，服务端自检通过不等于端到端可用
