# 自建服务端架构说明

## 组件一览

| 服务 | 端口 | 协议 | 职责 |
|---|---|---|---|
| `server.py` | 8443 | HTTP | 登录/注册/验证码/第三方登录接口；`lz4(bon)` 协议编码主入口 |
| `agentsrv.py` | 8765 | WebSocket | `/agent` 长连接，处理 236 个 `game_*` 指令，构造 `Game_RLogin` 等回包 |
| `admin.py` | 38443 | HTTPS | 后台管理面板（用户/信誉分/动态/审核/概览） |
| `proxysrv.py` | 8080 | HTTP CONNECT | 手机 WiFi 代理：游戏域名→本机，第三方 SDK→放行直连 |
| `dnssrv.py` | 53 | UDP DNS | 把 `*.hortorgames.com` 等劫持域名解析到 `PRIVSRV_IP` |
| `dotsrv.py` | 853 | DNS-over-TLS | Android「私人 DNS」通道，复用 dnssrv 的劫持逻辑 |
| nginx | 80 / 443 | HTTP / TLS | 按 SNI 与路径分发到后端/WS/静态资源 |

## 数据层

- 唯一数据源：`data/db.json`，`data/talks.json`
- `store.py`：用户库 / 会话 / 动态，跨进程 `flock` + 原子替换
- `features.py` + `feat_*.py`：社交/内容/编辑器/商城/OIM 等功能，数据存 `db.json` 的 `feat` 键，与 store 共用同一把锁
- `review.py`：头像审核队列
- 协议定义：`data/protocol.json`（响应类字段类型）、`data/data_schema.json`、`data/cmd_spec.json`（指令规格）

所有服务**每次读取都从文件 load（不缓存）**，所以后台改数据后，客户端重新登录即生效；功能数据由 `features.load_feat()` 用 `FEAT_DEFAULT` 自举，空库可用。

## 协议编码

客户端 `SendCmdAsync` 用 `bon` 序列化 + `lz4XorEncode`（LZ4 frame + 前 100 字节异或 + `pl` 头）。
- 编码：`server.py: lz4_xor_encode()` → 调 `lx_lz4.js`（`node_modules/lz4js`）
- `agentsrv.py` 负责 WS 帧的 `inflate_raw` / `bon_decode` / `bon_encode`
- 回包必须带 `resp=seq` 且 `decBody` 里放 `Game_RLogin` schema 合规字段，否则 `setValue` 解析失败 → 界面卡死

## 为什么需要 DNS/代理 + 根证书

客户端硬编码访问 `*.hortorgames.com`，这些域名官方已停服、无人解析。自建服务端通过：
1. `dnssrv/dotsrv` 或 `proxysrv` 把这些域名的连接导向**本机**；
2. nginx 用自签证书（`server.crt`，由本地根 CA 签发）完成 TLS；
3. 手机安装并信任该根 CA，客户端才会接受这个证书。

这三步全部在**你自己的服务器**完成，不依赖任何外部自建服务端。

## 客户端接入的两种路径

```
A. WiFi 代理: 手机 → 8080 proxysrv → (本地域名) 443/80 nginx → 后端/WS
B. 私人 DNS: 手机 → 53/853 dnssrv/dotsrv 解析到本机IP → 443 nginx → 后端/WS
```

`proxysrv` 的本地端口映射 `{80:80, 443:443, 38443:38443}`，保证后台 38443 经代理访问时直连（否则会被拐到 443，触发"下载文件"）。

## 信誉分机制（易踩坑）

- 客户端 `CreditMng.Ins.credit = 登录回包的 role.creditScore`，**只在登录时赋值一次**
- 语义是 **0~3 等级点**（`makeBro(叶子,3)`，`t<credit` 为绿），不是百分制
- `agentsrv.py` 登录回包读 `feat.credit[uid].score`（clamp 0~3），`game_getusercreditmsg` 返回明细
- 后台 `admin.py` 加/扣分写 `feat.credit` 与 `users[uid].creditScore`，并留一条明细
- 因此后台改动后需**退出重新登录**才刷新（客户端缓存，按原样保留，未改客户端）
