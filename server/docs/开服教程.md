# 从零搭建自建服务端 · 完整教程

> **本教程教你在一台【你自己的】服务器上，从零搭起一套完整、独立的自建服务端。**
> 装完之后，手机客户端连接的是**你这台服务器**，与任何其他服务器没有任何关系。
> 全程不需要、也不会连接到作者原来的机器——所有 IP、证书、密码、账号数据都在你自己的服务器上现场生成。

---

## 0. 先读：适用范围与前置说明

- 本教程面向**已停服软件的自用研究与单机复现**，请仅在个人学习、非商业、不传播的前提下使用。
- 本 `server/` 子目录只包含**服务端**代码。客户端相关资产位于复活包上级目录的 `client/`
  （原版基底、本地静态分析所得源码、参数化改包脚本），由 `docs/00_AI复活交接手册.md` 统一编排。
  本页只讲服务端部署，不涉及客户端改包。
- 目标游戏客户端为 Android 版，且需要把它的网络流量导向你的服务器（第 5 章讲怎么做）。
- 由于软件已停止官方服务，客户端访问的原域名已无人解析，本方案的思路是：**用 DNS/代理把原域名重新指向你的服务器，并由服务端模拟原协议回包**。

| 项目 | 要求 |
|---|---|
| 服务器 | 一台 Linux（Ubuntu 20.04+/Debian 11+/CentOS 8+），**有公网 IP**（或手机可直达的局域网 IP） |
| 权限 | root |
| 内存 | ≥ 1GB（建议 2GB） |
| 软件 | Python 3.8+、Node.js、nginx、openssl |
| 手机 | Android，与服务器网络可达（同 WiFi 或经公网） |

## 1. 整体架构（先看懂再动手）

客户端原本要连的是一堆 `*.hortorgames.com` 域名。自建服务端做的事是：**把这些域名的流量接到本机，由本机各服务分别应答**。

```
   手机客户端
      │  (原域名 *.hortorgames.com)
      │
      ├── WiFi 代理 :8080 ─────► [proxysrv 代理]  分流：游戏域名→本机，第三方SDK→放行
      │  或 私人DNS :53/:853 ──► [dnssrv/dotsrv]  把游戏域名解析到本机IP
      │
      ▼
   [nginx :443 / :80 ]  按 SNI / 路径分发
      │  /agent  ──────► [agentsrv :8765]  WebSocket，处理 200+ 个 game_* 指令
      │  其它HTTP ─────► [server.py :8443] 登录/注册/HTTP 接口
      │  /d/ /GameCreator-byte/ → uploads/ 静态封面资源
      ▼
   [data/db.json]  共享数据层（store.py / features.py，跨进程 flock 一致）
      ▲
   [admin.py :38443]  HTTPS 后台管理（改用户/信誉分/动态/审核）

   端口速查：
   80     nginx 明文 ws      443    nginx TLS(SNI)
   8443   HTTP 后端          8765   WebSocket agent（仅本机）
   38443  后台管理 HTTPS     8080   HTTP CONNECT 代理（手机连这个）
   53     DNS 劫持(UDP)      853    DoT(私人DNS, TCP)
```

> 8443 / 8765 只需本机内部访问，不必对公网开放；8080 / 443 / 80 / 53 / 853 / 38443 需要手机能连到。

## 2. 安装步骤

### 2.1 放到固定路径 `/opt/privsrv`

源码按固定路径 `/opt/privsrv` 编写（这样零配置、最不容易出错），**必须放到这个位置**。

在**复活交接包**里，服务端是包根的 `server/` 子目录，在包根执行：

```bash
sudo mkdir -p /opt/privsrv
sudo cp -a server/. /opt/privsrv/
cd /opt/privsrv
ls    # 应看到 admin.py server.py agentsrv.py conf/ data/ scripts/ docs/ ...
```

> 若你是把 `server/` 单独拿出来部署，把整个目录内容拷到 `/opt/privsrv` 即可：
> `sudo mkdir -p /opt/privsrv && sudo cp -a <你的server目录>/. /opt/privsrv/`

> 📌 本教程是**服务端通用参考**；整套复活流程（含客户端改包、IP 统一注入、真机验收）
> 以包根 `docs/00_AI复活交接手册.md` 为准，请先读那份。

### 2.2 填写你自己的服务器 IP

编辑 `conf/privsrv.env`：

```bash
sudo nano conf/privsrv.env
```

把这一行填上**你自己服务器的公网 IP**（手机能访问到的那个地址，不要填 127.0.0.1）：

```
PRIVSRV_IP=1.2.3.4
```

> 这一步是"连自己服务器"的核心：DNS 会把游戏域名解析到这个 IP，证书也会为这个 IP 签发，
> 代理白名单也用它。**全包不含任何写死的他人 IP**，所有服务都从这里读。

其余可选项（一般留默认）：
- `PRIVSRV_UPSTREAM`：上游 DNS，默认 `223.5.5.5`
- `PRIVSRV_DOMAIN`：Android 私人 DNS 用的域名，留空则自动用 `<IP 横线分隔>.nip.io`
- `NODE_BIN`：node 路径，留空自动从 PATH 找

### 2.3 运行一键安装

```bash
sudo bash scripts/install.sh
```

脚本会自动完成 7 件事：

1. 检查 `python3 / node / openssl / nginx` 与 Python 依赖（`flask bcrypt websockets`）
2. 确认/写回 `PRIVSRV_IP`
3. **生成全套自签证书**（`scripts/gen_certs.sh`）：根 CA、游戏域名证书、后台证书、DoT 证书，SAN 全部带**你的 IP**
4. **初始化后台随机密码**（`scripts/init_admin.sh`）：bcrypt 哈希 + 会话密钥，密码存 `admin_password.txt`
5. 建目录、权限、Python 语法自检
6. 放置 nginx 配置（标准 `/etc/nginx/conf.d/` 或宝塔路径）并重载
7. 安装并启动 6 个 systemd 服务

> 手动分步执行也可以，见 `docs/手动部署.md`。

安装完成后会打印：
- 后台地址 `https://<你的IP>:38443` 和随机密码
- 根 CA 路径 `uploads/privsrv-ca.crt`
- 客户端接入方式

### 2.4 放行防火墙 / 安全组

**云服务器务必在控制台安全组放行**：`80, 443, 8080, 38443, 53, 853`（TCP）+ `53`（UDP）。

系统防火墙（若开启）：

```bash
# ufw
sudo ufw allow 80,443,8080,38443,853/tcp
sudo ufw allow 53
# firewalld
sudo firewall-cmd --add-port=80/tcp --add-port=443/tcp --add-port=8080/tcp \
  --add-port=38443/tcp --add-port=853/tcp --add-port=53/tcp --add-port=53/udp --permanent
sudo firewall-cmd --reload
```

## 3. 验证服务端起来了

```bash
cd /opt/privsrv
bash scripts/check.sh          # 逐项自检（服务/端口/证书/回包）
bash scripts/ctl.sh status     # 6 个服务状态
bash scripts/ctl.sh logs       # 看最近日志
```

正常的自检结果应为「全部正常」。也可以手动验证：

```bash
curl -k https://127.0.0.1:38443/login        # 后台登录页
curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8443/   # 后端
python3 scripts/ws_probe.py                   # WS game_login 回包探针
```

后台打开 `https://<你的IP>:38443`，用 `admin_password.txt` 里的密码登录。
> 首次浏览器会提示证书不受信任——因为用的是自签证书，点「继续访问」即可；
> 想彻底消除提示，把根 CA 装进电脑/手机的信任证书（第 5 章）。

## 4. 手机客户端接入（让客户端连【你的】服务器）

**二选一**，推荐先用 A 验证，A 不通再试 B。两种方式都只连你自己的服务器。

### 方式 A：WiFi 代理（最简单，推荐）

1. 手机连上与服务器**网络可达**的 WiFi
2. WiFi 设置 → 修改网络 → 高级 → 代理「手动」：
   - 代理主机名：`<你的服务器IP>`（就是 `PRIVSRV_IP`）
   - 代理端口：`8080`
3. 安装并信任根证书（下一步）

### 方式 B：私人 DNS（Android 9+，无需改代理）

1. 手机 设置 → 连接 → 私人 DNS（Private DNS）→ 选「指定私人 DNS 主机名」
2. 填 `conf/privsrv.env` 里 `PRIVSRV_DOMAIN` 的值（默认 `<IP横线>.nip.io`），或服务器 IP
3. 安装并信任根证书

> `dnssrv`(53) / `dotsrv`(853) 会把 `*.hortorgames.com` 等游戏域名解析到你的服务器 IP，
> 其它域名正常转发到上游 DNS，不影响手机正常上网。

### 安装根证书（关键，必须做）

客户端走 HTTPS，会校验服务器证书。因为自建服务端是自签证书，**手机必须信任你的根 CA**，否则连接会被拒。

1. 把 `/opt/privsrv/uploads/privsrv-ca.crt` 传到手机
   - 可在浏览器打开 `http://<你的IP>:8080` 前先直接拷贝文件，或
   - `https://<你的IP>/d/privsrv-ca.crt`（经 nginx `/d/` alias 到 uploads/）
2. Android：设置 → 安全 → 加密与凭据 → 从存储设备安装 → 选择该 `.crt` → 命名为「自建服务端CA」→ 安装
3. 部分 Android 版本需额外在「信任的凭据 → 用户」里确认已启用

> 这个 CA 是**你自己在安装时生成的**，与任何其他人的证书无关。

### 完成

启动客户端 → 用**任意手机号 + 任意验证码**登录（自建服务端自动注册/复用账号）→ 进入即可。
后台 `https://<你的IP>:38443` 会实时看到新注册的用户。

## 5. 后台管理功能

| 功能 | 位置 |
|---|---|
| 用户列表 / 编辑任意字段（G币、钻石、等级、昵称、蓝V…） | 用户 → 点具体用户 |
| **信誉分加/扣**（0~3 等级点，填理由） | 用户详情页底部「信誉分管理」 |
| 动态（说说）编辑 / 删除 / 清空 | 动态 |
| 头像审核队列 | 头像审核 |
| 功能数据总览 / 重置 | 功能数据 |
| 概览统计 | 首页 |

**信誉分说明**：客户端是 0~3 的「叶子」制（满 3 全绿，每扣 1 点掉 1 片，0 = 全灰=违规锁定）。
后台扣分/加分后，客户端需**退出重新登录**才会刷新叶子与明细（客户端自身缓存机制，原样保留）。

## 6. 常见问题与排错

| 现象 | 原因 / 处理 |
|---|---|
| 后台每次操作都提示「下载一个东西」 | 后台走 8080 代理时，代理必须把 `38443` 直连。本包 `proxysrv.py` 已内置 `{80:80,443:443,38443:38443}` 映射；确认用的是本包版本 |
| 手机打不开 / 连不上 | ① 安全组/防火墙没放行 8080/443/53/853 ② `PRIVSRV_IP` 填错 ③ 手机与服务器网络不通（先 `ping` / `telnet IP 8080`） |
| 反复「登录失败 / 重试」 | 根 CA 没装或没信任；或 nginx 未重载 / 证书路径不对（`nginx -t` 检查） |
| 登录进去了但界面空白 | 看 `bash scripts/ctl.sh logs` 里 agentsrv 是否报错；确认 8765 WS 正常（`python3 scripts/ws_probe.py`） |
| 扣分后叶子还是全绿 | 需要**退出重新登录**（客户端把信誉分缓存在登录时）；另确认 `agentsrv` 是最新版 |
| 信誉分一直是 3 / 明细空 | 服务端登录回包读 `features` 的信誉分；本包已修正。重启 `agentsrv` 后重登 |
| DNS 不生效 | 确认 53(UDP)/853 已放行且未被运营商劫持；优先用方式 A 的 WiFi 代理 |
| 后台密码忘了 | `sudo rm /opt/privsrv/data/admin_auth.json && sudo bash scripts/init_admin.sh` 重新生成 |
| node 报错 / lz4 编码失败 | 确认 `node` 在 PATH；或设 `NODE_BIN=/path/to/node` 到 `conf/privsrv.env` |
| 想换服务器 IP | ①改 `conf/privsrv.env` 的 `PRIVSRV_IP` → 重跑 `gen_certs.sh` → 重启服务 → 手机重装新根 CA；**②客户端必须用新 IP 重新执行 `build_revived_apk.py` + `sign_apk.sh` 重装**（客户端 jsc 里写死了 IP，不重打包会连回旧机）。复活包里改包根 `conf/revive.env` 后跑 `sync_ip.sh` 可一次性对齐两端 |

改完配置后统一重启：

```bash
sudo bash scripts/ctl.sh restart
```
