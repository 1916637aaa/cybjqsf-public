# 服务端运维速查

> 服务端部署到 `/opt/privsrv` 之后使用。所有命令均在该目录下或 systemd 层执行。

## 服务管理

```bash
cd /opt/privsrv
bash scripts/ctl.sh status          # 查看 6 个服务状态
bash scripts/ctl.sh restart         # 全部重启
bash scripts/ctl.sh logs privsrv    # 看某服务日志
bash scripts/check.sh               # 自检：端口/证书/后台/WS game_login
```

或直接用 systemd：
```bash
systemctl is-active privsrv agentsrv privsrv-admin privsrv-proxy privsrv-dns privsrv-dot
systemctl restart agentsrv
journalctl -u privsrv-proxy -f
```

## 日志

| 路径 | 内容 |
|---|---|
| `/opt/privsrv/logs/requests.jsonl` | App 实际发来的 HTTP 请求（补兜底接口时看它） |
| `/opt/privsrv/logs/proxy.log` | 代理 CONNECT 分流日志 |
| `journalctl -u <服务>` | 各服务标准输出 |

## 数据

- 主库：`/opt/privsrv/data/db.json`（干净空库自举，删掉恢复初始）
- 动态：`/opt/privsrv/data/talks.json`
- 协议定义：`/opt/privsrv/data/protocol.json`、`cmd_spec.json`、`data_schema.json`
- 审核配置：`data/review_cfg.json`；代理白名单：`data/ip_whitelist.json`（`strict=true` 时仅名单内 IP 可连 8080）

- **代理默认只放行「有关域名」**：`proxysrv.py` 默认开启域名严格模式（`PROXY_STRICT` 环境变量，缺省 `true`）。
  仅放行自建服务端域名（`*.hortorgames.com` / `*.hortorinteractive.com` / 自建环境 IP / localhost），
  其余 **CONNECT 隧道和明文 HTTP 代理请求（GET http://...）一律 403 拒绝**。
  两条分支共用 `allowed()` 判定，明文分支额外校验 Host 头与绝对 URL 里的域名，
  防止「CONNECT 被挡后改用明文 HTTP 继续当免费代理」的绕过。
  这从根上防止本机被当成免费开放代理滥用（境外受限站点、Google/GitHub、广告聚合等都无法经此转发）。
  - 关闭严格模式（退回放行全部第三方 SDK 域名的旧行为）：`PROXY_STRICT=0`
  - 严格模式下额外放行极少数第三方域名：`PROXY_REMOTE_ALLOW=a.qq.com,b.qq.com`
    （逗号分隔，**精确主机名**，需写全；代码用 `h in REMOTE_ALLOW`，不是后缀匹配）
  - 来源 IP 白名单：`data/ip_whitelist.json` 的 `strict=true` 时，**仅 `allow` 名单内 IP + 本机能连 8080**；
    手机公网 IP 会变动，开启前务必确认当前出口 IP 已写入 `allow`，否则手机会连不上代理。
  - **拒绝日志已节流**（同一被拒域名每 300 秒最多记一条 warning），避免 syslog 被刷爆。
  - 下载服务 `privsrv-dl` 的访问日志**不写 syslog**（独立小文件或静默），同样为避免磁盘写满。
- 读写请走 `store.load_db()` / `store.save_db()`，不要直接手改 JSON

## 证书 / 密码

```bash
bash scripts/gen_certs.sh     # 用 conf/privsrv.env 的 PRIVSRV_IP 重签 CA+server+admin+dot
bash scripts/init_admin.sh    # 重置后台密码（随机生成，写入 admin_password.txt）
```
- 根 CA 分发给手机：`/opt/privsrv/uploads/privsrv-ca.crt`
- 后台密码：`/opt/privsrv/admin_password.txt`

## 后台功能（https://<IP>:38443）

- 用户列表 / 某用户详情：作品、金币、**信誉叶子管理（扣叶子 + 理由）**
- 信誉叶子是 **0~3 等级点**：满 3 全绿，扣 1 掉 1 片叶子，扣到 0 即封号
- 后台「举报处罚」下拉写的是**扣叶子**（扣1片/扣2片/扣3片），底层仍是 `creditScore`，文案与客户端一致
- 改完后台数据后，客户端需**退出账号重新登录**才刷新（客户端只在登录时读一次叶子）
- 登录回包 `creditScore` 与 `game_getusercreditmsg` 明细都读真实值

## 封号闭环（v1.1.0 新增）

> 设计取舍：客户端**断线会无条件重连**、且**没有「服务端主动弹操作窗」的通道**，
> 所以封号不是「拒绝登录」，而是「**能登录、看得到封号公告、但所有写操作被服务端封死**」。

| 环节 | 实现 | 文件 |
|---|---|---|
| 触发 | 后台举报处罚选「扣3片」使叶子归 0，或 IP 风控页「封禁账号」 | `admin.py` |
| 立即掉线 | 后台写 `data/kick.jsonl`，`agentsrv` 轮询后关闭该 uid **全部** WS，`code=4001` | `admin.py` / `agentsrv.py` |
| 登录弹窗 | 登录回包注入 `Notice`（标题客户端写死为「公告」，正文带醒目封禁头 + 受限功能清单），版本默认 `0.8.10` | `agentsrv.py` |
| 功能限制 | 服务端拦截 89 条写指令（发布/编辑/搜索/评论/点赞/收藏/私信/改资料/举报等），**不落库**，回包 `code=0`、`success=false` 保证客户端不卡死 | `agentsrv.py` |
| 操作反馈 | 被拦截时写 `kick.jsonl` 触发重连，重连后再次弹出封号公告（30 秒节流，避免刷屏） | `agentsrv.py` |
| 信誉页提示 | 明细顶部注入一条醒目提示：账号已被封禁、叶子扣至0、全部功能受限 | `feat_content.py` |

- 客户端**叶子 UI 只在登录时赋值**，信誉页还缓存 3 片是客户端显示问题；服务端以封号公告 + 明细提示兜底。
- 想换 APP 版本时改 `db.json` → `feat.ban_notice_version`（默认 `0.8.10`），公告只对匹配版本弹出。
- 解除封号：后台把叶子加回 3，并清空 `data/kick.jsonl` 后重登即可。

## 常见维护动作

| 需求 | 做法 |
|---|---|
| 换服务器 IP | 改 `conf/privsrv.env` 的 `PRIVSRV_IP` → `gen_certs.sh` 重签 → 重启服务 → **客户端也要用新 IP 重打包** |
| 补一个兜底接口 | 看 `logs/requests.jsonl` 找到真实路径 → 在 `server.py` 加路由 → 重启 privsrv |
| 看客户端实际请求了什么 | `tail -f logs/requests.jsonl` 或 `https://platform.hortorgames.com/_admin/paths` |
| 恢复出厂 | 停服务 → 用干净 `data/db.json` 覆盖 → 启动（`load_feat` + `seed` 自动补齐） |
