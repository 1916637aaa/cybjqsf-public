## 0. 你必须先知道的三件事

1. **本包不含任何旧服务器 IP、不含任何真实账号数据、不含后台密码。**
   唯一要填的是 `conf/revive.env` 里的 `YOUR_SERVER_IP=<新服务器公网IP>`。
   所有脚本从这个值注入地址，代码与文档里都是占位符。

2. **本包含完整服务端；客户端只提供研究工具，不提供安装包。**
   服务端是纯 Python 自实现（`server/`），不连任何官方服务器；
   客户端需你自备同版本原版安装包，再用 `client/tools/` 在本地处理。
   XXTEA 解密密钥 `ce27dc26-f6dc-47` 在 `docs/01_客户端改动清单.md`，是反编译得到的研究用常量。

3. **合规边界**：本项目用于**个人研究/自用**在自有服务器上重建。请勿公开传播、
   勿商业化、勿分发客户端安装包给他人。

## 1. 系统架构（先看懂再动手）

```
手机 APP (改包后)
   │
   ├─ WS 明文  ws://<IP>/agent          → nginx:80  → agentsrv:8765   【登录/主逻辑，236 个 game_* 指令】
   ├─ HTTP/HTTPS https://*.hortorgames.com/... → nginx:443 → privsrv:8443 【/agent、上传、审核等】
   ├─ HTTP  http://<IP>/hotfix.js /hf   → nginx:80  → privsrv:8443   【远程热修/状态上报】
   │
   └─ 域名怎么指到本机？两种方式二选一/并用：
        A. WiFi 代理  <IP>:8080   → proxysrv（HTTP CONNECT，按域名白名单直连本机 nginx，不解析真实域名）【推荐】
        B. DNS 劫持   UDP53/DoT853 → dnssrv/dotsrv 把 *.hortorgames.com 解析到 <IP>
        ※ 后台管理面板： https://<IP>:38443 （admin.py，独立 HTTPS）
```

| 组件 | 文件 | 端口 | 作用 |
|---|---|---|---|
| `privsrv` | `server.py` | 8443（经 nginx 443/80） | HTTP 后端：`/agent`、上传、hotfix、审核状态 |
| `agentsrv` | `agentsrv.py` | 8765 | WebSocket 后端：236 个 `game_*` 指令 |
| `privsrv-admin` | `admin.py` | 38443 | 后台管理（用户/作品/信誉分/审核） |
| `privsrv-proxy` | `proxysrv.py` | 8080 | HTTP CONNECT 代理 + 域名白名单分流 |
| `privsrv-dns` | `dnssrv.py` | 53 | 普通 DNS 劫持 |
| `privsrv-dot` | `dotsrv.py` | 853 | DNS-over-TLS 劫持 |
| nginx | `conf/nginx/privsrv.conf` | 80/443 | 七层反代 + TLS 终止（自签 CA） |

**关键依赖**：`lx_lz4.js` + `node_modules/lz4js`（LZ4/XOR 协议编码，server.py 通过 `node` 调用）、
Python `flask / bcrypt / websockets`、JDK + Android build-tools（`keytool/zipalign/apksigner`，仅客户端签名用）。

## 2. 环境要求

- 一台有**公网 IP** 的 Linux 服务器（Ubuntu 22.04 验证过），root 权限
- 放行端口：`80 / 443 / 8080 / 38443`，另 `53 / 853`（若用 DNS 方式）
- `python3` + `pip`、`node`（能 `require('lz4js')`）、`nginx`、`openssl`
- 客户端签名需要 `keytool`、`zipalign`、`apksigner`（`apt install openjdk-17-jdk-headless apksigner zipalign` 或 Android SDK build-tools）
- 一台 Android 手机用于真机验收（AI 无法替代此步）

## 3. 第 1 步 · 填 IP（唯一必填项）

```bash
cd <解压出来的 privsrv-revive-kit>
vi conf/revive.env
#   YOUR_SERVER_IP=<新服务器的公网IP>
#   FORBID_IPS=<可选：旧服务器IP，用于校验成品绝不连回旧机>
bash scripts/sync_ip.sh      # 把 IP 同步进 server/conf/privsrv.env
```

`sync_ip.sh` 会把该值写进 `server/conf/privsrv.env` 的 `PRIVSRV_IP`，
**服务端与客户端从此共用同一个 IP**，避免「服务端是新的、客户端还连旧的」。

## 4. 第 2 步 · 部署服务端

> 服务端源码按固定路径 `/opt/privsrv` 编写（`install.sh` 会强校验），必须放到这个位置。

```bash
sudo mkdir -p /opt/privsrv
sudo cp -a server/. /opt/privsrv/
cd /opt/privsrv
sudo bash scripts/install.sh
```

`install.sh` 一条命令做完：依赖检查 → 写 IP → 现场生成自签 CA+server+admin+dot 证书
（SAN 带**新 IP** 与 `*.hortorgames.com`）→ 生成随机后台密码 → 装 nginx 配置 →
安装并启动 6 个 systemd 服务。

验收：
```bash
cd /opt/privsrv && bash scripts/check.sh
systemctl is-active privsrv agentsrv privsrv-admin privsrv-proxy privsrv-dns privsrv-dot
curl -sk https://127.0.0.1:38443/login -o /dev/null -w '%{http_code}\n'   # 期望 200
```

> 后台密码在 `/opt/privsrv/admin_password.txt`（安装时现场生成，本包内没有）。

### 4.1 nginx 是最容易踩坑的地方（务必读）

本包 `conf/nginx/privsrv.conf` 是**标准七层配置**：
- `listen 80 default_server` 处理明文 `ws://<IP>/agent`（`location /agent` → 8765）与 `/hotfix.js`（→ 8443）
- `listen 443 ssl` + `server_name *.hortorgames.com ...` 处理 HTTPS

**若目标机器上已有 nginx 站点（尤其宝塔面板）**：
- `default_server` / `server_name` 可能与现有配置冲突，`nginx -t` 会失败；
- `install.sh` 对 nginx 失败只**警告不中断**，会出现「6 个服务全 active，但客户端连不上」。

**你的处理动作**：
1. `nginx -t` 看具体冲突，把本模板的 `server` 块合并进现有配置，或改用 `include` 到 `conf.d/`；
2. 若原架构用的是**四层 stream + ssl_preread（SNI 分发）**，需要按 SNI 把 `*.hortorgames.com` 转给后端，
   而不是七层 `server_name`——两种不等价，别直接套；
3. 改完 `nginx -s reload`，用 `curl -k https://127.0.0.1/_admin/state` 或经代理验证。

## 5. 第 3 步 · 重建客户端（V3 等价物）

**为什么不放成品**：历史成功版 V3 的 `index.jsc` 里编译进了旧服务器 IP，
直接沿用会连回旧机。本包改为「原版基底 + 参数化补丁」，用新 IP 现场生成等价版本。
4 处改动的逐字说明见 `docs/01_客户端改动清单.md`。

```bash
cd <包根>
NEWIP=$(grep '^YOUR_SERVER_IP=' conf/revive.env | cut -d= -f2-)

# ① 打补丁（解密 jsc → 改 4 处 → 重新加密 → 重建未签名 APK）
PRIVSRV_IP=$NEWIP python3 client/tools/build_revived_apk.py

# ② 重签名（现场生成 keystore，zipalign + apksigner v1/v2/v3）
bash client/tools/sign_apk.sh

# ③ 校验：地址是否指向新 IP、补丁是否齐全、是否残留旧 IP
python3 client/tools/verify_apk.py --expect-ip "$NEWIP"
# 若 conf 里填了 FORBID_IPS，会自动断言成品不含旧地址
```

产出：`client/out/创游编辑器_复活版_已签名.apk`

**脚本会自己做的硬校验**（失败会直接报错退出，不要跳过）：
XXTEA round-trip 字节一致 → 每个补丁锚点在原版里 `count==1` → IP 占位符恰好 2 处 →
jsc 回读一致 → 重建后除签名外仅 `index.e248a.jsc` 被改动。

> 若锚点 `count != 1`，说明 `client/base/` 里的基底 APK 版本与 V3 制作时不同。
> **不要硬改**——先用 `client/tools/extract_all.py` 解密基底，到 `client/src/` 里 grep 定位真实锚点，
> 再调整 `build_revived_apk.py` 的 `PATCHES`。

## 6. 第 4 步 · 手机接入（AI 做不了，交给持有者）

AI 请把下面这段转述给持有者照做：

1. **先卸载原版 APP**（签名不同，覆盖安装必定失败），再安装 `创游编辑器_复活版_已签名.apk`
2. 安装根证书 `certs/privsrv-ca.crt`（服务端 `gen_certs.sh` 生成）：
   设置 → 搜索「安装证书」→ 类型选 **CA 证书**（别选成「VPN 和应用」）
3. 私人 DNS 改回「**自动**」（若曾设过 DoT）
4. 配置代理（推荐方式）：WLAN 长按当前 WiFi → 修改网络 → 高级 → 代理「手动」
   - 代理主机名：`<新服务器IP>`
   - 代理端口：`8080`
   流量网络则用免 root VPN 工具（如 Postern）建 HTTP 代理、规则全局
5. 打开 APP：**手机号随便填，验证码固定 `1234`**（QQ/微信登录因重签名已失效）

### 6.1 客户端接入的隐性知识（这几条不在别处，最容易忘）

- 客户端把 `*.hortorgames.com` 系列域名**硬编码**在代码里，不改包换域名（V3 只改了 WS 地址，
  HTTP 业务仍走这些域名），所以必须靠**代理白名单或 DNS 劫持**把域名指到新服务器。
- `proxysrv.py` 的 `ALLOW_EXACT` / `LOCAL_SUFFIX` 只放行 `<新IP>`、`127.0.0.1`、`localhost`
  与 `hortorgames.com` / `hortorinteractive.com` 后缀。若后台用了别的域名，要加进白名单。
- 代理对 **38443 后台端口有专门直连映射**（`{80:80, 443:443, 38443:38443}`），
  否则经代理访问后台会被错拐到 443，浏览器弹「下载一个东西」且操作失败。
- **Android 7+ 默认不信任用户 CA**。若 HTTPS 校验证书链失败，要么确保 CA 装成系统级、
  要么在 `AndroidManifest`/`network_security_config` 里声明信任用户 CA（本包未强制改此项，
  因为 V3 实测在持有者设备上通过「安装 CA 证书」已可用）。
- WS 用**明文 `ws://`** 直连 IP（不走 TLS），所以登录链路不吃证书；
  HTTPS 业务接口才需要 CA。

## 8. 排错速查

| 现象 | 大概率原因 | 处理 |
|---|---|---|
| 6 服务全 active 但 APP 连不上 | nginx 配置冲突/未重载 | `nginx -t`；合并 server 块；`nginx -s reload` |
| 一直卡「登录中/转圈」 | WS 没通：`ws://<IP>/agent` 的 80 端口 `/agent` 未转发到 8765 | 查 nginx 80 的 `location /agent`；`curl` 测 |
| 经代理操作后台弹「下载一个东西」 | 38443 被拐到 443 | 确认 proxysrv 端口映射含 38443 |
| 验证页 `no Route matched` | 代理没生效 / APP 不走系统代理 | 换 VPN 全局代理方式 |
| 设代理后其他网页打不开 | 代理只转发 hortor 域名 | 正常，不用时改回「无」 |
| 浏览器提示证书不受信 | CA 没装或装错类型 | 重装，类型选「CA 证书」 |
| 首页 tab 在但内容空白 | 补丁 1/2 没生效 / 锚点没匹配 | 检查 build 脚本输出；`verify_apk.py` 查标记 |
| 安装 APK 提示「应用未安装」 | 没卸载原版 / 签名未做 | 先卸载；`apksigner verify` 确认有 v2 签名 |
| APP 能开但第三方登录失败 | 重签名导致 AppId 指纹不匹配 | 用手机号 + 验证码 `1234` |
| 后台改了信誉分但 APP 叶子不变 | 客户端只在登录时读一次 `creditScore` | **退出账号重新登录**（持有者已确认按原样，不改客户端） |

## 9. 已知踩坑记录（前人踩过，别重踩）

1. **信誉分是 0~3 等级点，不是百分制**。客户端 `makeBro(叶子, 3, t<credit)` 固定画 3 片叶子，
   满 3 全绿、扣 1 掉 1 片、扣到 0 = 功能全锁。**若按 100 分制存，客户端永远 3 片绿**。
   后台 `adjust_credit` 与登录回包都已 clamp 到 0~3。
2. **`agentsrv.py` 里没有 `F` 这个别名**。历史 bug：`F.as_int(...)` 抛 `NameError` 被
   `except: pass` 吞掉，导致登录回包信誉分恒为默认 3、明细恒空。正确写法用 `features.as_int`。
   排错时若「明细是新的、叶子不变」，先查这类被静默吞掉的异常。
3. **`game_getusercreditmsg` 曾返回空列表**，信誉明细界面读不到记录；现已返回真实
   `userCreditMsgList` + 恢复进度。
4. **信誉分归零不会强制退登/不弹「账号被封禁」**——原版客户端根本没有该逻辑，
   归零只是「功能全锁 + 全灰叶子 + 显示恢复进度条」，人能一直待在 APP 里。
5. **lz4 编码模式**：`lx_mode` 必须是 `frame`（`lx_seq` 归 0）。改错会导致客户端解码失败。
6. **空库自举**：`db.json` 是干净空库，`features.load_feat()` 会自动补齐 31 个键，
   `server.seed()` 自动造 5 个示例作品与公告。首次登录自动注册，无需预置账号。
7. **代理/DNS 择一即可**：推荐代理（不解析域名、不受运营商 DNS 劫持与 853 封端口影响）。
8. 手机接入指南原文在 `docs/` 可查；本包已把其中旧 IP 全部改成占位符。
