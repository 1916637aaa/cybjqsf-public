# 客户端改动清单（V3 修复版 · 逐字还原）

> 本文回答两个问题：**客户端到底改了什么**、**换服务器时必须改哪里**。
> 历史上真机验证成功连上自建服务端的最终版本代号 **V3**。本包不放 V3 成品（见文末），
> 而是提供 `client/tools/build_revived_apk.py` 参数化复刻它。
>
> **用途与边界**：以下内容是持有者对**自己已有的本地安装包**做静态分析的结果，
> 只用于理解通信协议、把自用环境在一台**自有服务器**上跑通。标的软件官方已停服多年，
> 本分析不涉及、也不用于访问任何第三方系统或获取他人数据；本文及其中的常量、脚本
> **不对外提供**。完整背景见包根目录《请先阅读_事实背景与合规边界.md》。

## 0. 加密格式与密钥（最重要，先记住这个）

APK 主逻辑在 `assets/assets/main/index.e248a.jsc`，是 **XXTEA + gzip 双层加密**：

```
.jsc = XXTEA( gzip( 源码.js ) )
```

| 项 | 值 |
|---|---|
| XXTEA 密钥 | **`ce27dc26-f6dc-47`**（16 字节 ASCII） |
| 密钥来源 | 硬编码在 `lib/armeabi-v7a/libcocos2djs.so` 的 `.rodata`（Cocos 编译期常量，Java 层无 `setXXTEAKey`） |
| 长度字 | Cocos `include-length` 格式：解密后**最后一个 word = 原始明文长度**，必须据此裁切 |
| gzip | 解密后是 gzip 流（`1f 8b 08`），需再解压 |
| 回写 | `gzip.compress(mtime=0)` → 补齐到 4 字节对齐 → 末尾追加长度 word → XXTEA 加密 |

一键解密工具：`client/tools/extract_all.py`（仅标准库），产出 `client/src/` 下全部可读源码。
主逻辑 `client/src/assets/main/index.e248a.js` 约 240 万字符 / 4.7 万行，是格式化过的多行源码，
带真实类名方法名，**不是混淆代码**，可直接 grep 定位。

> 密钥也可用结构性判据从本地文件推导：解密后长度字须落在 `[文件大小-7, 文件大小-4]`。
> 但没必要，密钥已在上表给出。（这是对本地文件的静态格式校验，不涉及任何在线系统。）

## 1. V3 的 4 处改动（都在 `index.e248a.jsc` 里）

### 改动 1 · HomeScene.onLoad 主动加载默认主页面

**为什么**：`ToggleGroup.onLoad` 初始派发的 `TOGGLE_CHANGE` 事件早于监听注册，
导致 `HomeScene` 的内容子页从未被实例化，表现为「首页内容区空白」（框架 tab 栏在、里面是空的）。

**锚点**（原版原文）：
```js
onLoad() {
this.toggleGroup.node.on(r.default.TOGGLE_CHANGE, this.onToggleChange, this);
this.createBtn.node.on(T.default.CLICK, this.onTapCreate, this);
}
```
**改为**：在 `}` 前插入
```js
setTimeout(() => { try { (window.__psrvR || function(){})("HS onLoad"); this.onToggleChange(0); } catch (e) { (window.__psrvR || function(){})("HS ERR " + e); } }, 0);
```

### 改动 2 · DiscoverPage.onLoad 内联直接加载默认内容子页

**为什么**：v2 试过直接调 `onToggleChange(0)` 无效——它是 async generator，
① 内部 `if (e !== this.toggleGroup.idx) return` 会静默返回；
② 抛出的异常变成 rejected Promise，调用处 `try/catch` 抓不到，日志零线索。
所以 v3 改为**绕开 onToggleChange**，直接 `loadBundleRes → instantiate → addChild`，并把异常全部上报。

**锚点**（`d.Util.makeBro(...)` 那段末尾的 `});` 之后）：
```js
d.Util.makeBro(this.toggle.node, this.datas.length, (e, t) => {
let o = e.getComponent(s.default), i = this.datas[t];
o.label.string = i.name;
d.Util.updateLabel(o.label);
o.node.width = o.label.node.width + 40;
d.Util.updateAllWidget(o.node);
});
}
```
**改为**：在 `});` 与 `}` 之间插入 `DP_PATCH`（完整代码见 `build_revived_apk.py` 的 `DP_PATCH` 常量）。
要点：`setTimeout(300)` → 重置 `toggleGroup.idx/lastIdx = 0` → 取 `datas[0].prefab`
→ `d.Util.loadBundleRes('Scene/HomeScene/DiscoverPage/' + nm)` → `cc.instantiate` →
`self.content.addChild(node)` → 失败重试 3 次（间隔 700ms），每步状态经 `R()` 上报。

### 改动 3 · WS 直连自建环境 IP ★ 换服务器必改 ★

**为什么**：手机 DNS 不解析自建服务端域名，WebSocket 明文 `ws://` 连不上，卡在「登录中」。
V3 把地址写死成直连 IP。

**锚点**：
```js
let o = d.gameEnv.urlRoot + "/agent";
```
**改为**：
```js
let o = "ws://<新服务器IP>/agent";
```

> 这是**换服务器时最关键的一处**。旧成品里写死的是旧服务器 IP，
> 不改的话客户端会一直连回已经停用的旧机，表现为「一直转圈 / 登录失败」。

### 改动 4 · 远程热修通道 + 状态上报 ★ 换服务器必改 ★

在 webpack bundle 末尾追加一个独立自执行 IIFE（`LOADER`），作用：
- 定义 `window.__psrvR(m)`：把状态用 `GET http://<IP>/hf?m=...` 上报（供 `journalctl` 排错）；
- 启动后 `GET http://<IP>/hotfix.js` 拉远程热修脚本并 `eval`，以后服务端改逻辑即刻生效、无需重装 APK；
- 全程异步、全 `try/catch`、不阻塞启动。

```js
var BASE = 'http://<新服务器IP>';
```

> 第二处写死 IP。服务端 `/hotfix.js` 与 `/hf` 路由由 `server.py` 提供（`/cmd` 也可下发调试指令）。

### 附带：保持原生自动重登分支

不要像 v2 那样强制 `t = null`（那会破坏第三方 SDK 登录）。V3 保留原生：
```js
let e = r.PlatType.Visitor, t = l.crossPlatform.getStorageSync(E.SaveDefines.KeyLoginType), o = !1;
```
第三方 SDK 由代理白名单放行即可。

## 2. 重打包与签名流程

```
原版 APK (client/base/)
   │  ① 解密 index.jsc → 打 4 处补丁 → 重新 gzip+XXTEA 回写
   │  ② 保留 APK 全部条目重建，仅替换 jsc、剔除 META-INF 旧签名
   ▼
未签名 APK (client/out/创游编辑器_复活版_未签名.apk)
   │  ③ zipalign -p 4
   │  ④ apksigner sign（现场生成新 keystore，v1+v2+v3）
   ▼
已签名 APK (client/out/创游编辑器_复活版_已签名.apk)  ← 装进手机
   │  ⑤ verify_apk.py 校验 IP 与补丁
   ▼
安装
```

**签名密钥不需要找回**：`apksigner` 验证可见原版 `CN=Hortor`、V3 `CN=PrivSrv Fix`、
免root版 `CN=cybjq-privsrv` 是三套完全不同证书——历史上每次重打包都是**现场另生成一把**。
`sign_apk.sh` 同样现场生成 `revive.jks`，口令写在脚本里，不依赖任何旧密钥。

**签名带来的两个必然后果**（不是故障）：
1. 签名与原版不同 → 手机**必须先卸载原版**，覆盖安装必定失败；
2. QQ / 微信登录的 AppId 绑原签名指纹 → **重签名后第三方登录必然失效**，只能用手机号登录
   （自建服务端验证码固定 `1234`，手机号随便填）。

## 3. 为什么本包不放 V3 成品 APK

V3 成品里 `ws://旧IP/agent` 和 `http://旧IP` 是**编译进加密 jsc 的**，
明文 `grep` 扫不到、但解密后确实存在。直接沿用会连回旧服务器，正是换服务器时要避免的。

因此本包给的是：
- **原版基底 APK**（干净，不含任何自建环境 IP）—— `client/base/`
- **参数化补丁脚本**（IP 由 `PRIVSRV_IP` 注入，代码里零真实 IP）—— `client/tools/build_revived_apk.py`
- 用新 IP 跑一遍，得到与 V3 **等价、但指向新服务器**的客户端。

这样「教程里不出现旧 IP」与「能复活出成功版本」两个要求同时满足。

## 4. 自检要点（交给新 AI 时必须验证）

| 检查 | 方法 |
|---|---|
| XXTEA 加解密正确 | 脚本内 `round-trip` 断言：原密文解密再加密必须逐字节还原 |
| 补丁锚点唯一 | 每个 anchor 在原版 js 里 `count == 1`，否则说明基底 APK 版本不匹配，**不要硬改** |
| jsc 回读一致 | 新密文解密解压后 == 新源码字节 |
| 只改了 jsc | 重建后比对，除 `META-INF` 签名外仅 `index.e248a.jsc` 不同 |
| IP 注入完整 | 占位符 `__SRV_IP__` 恰好出现 2 次且全部替换 |
| 成品不连旧机 | `verify_apk.py --forbid-ip <旧IP>` 断言二进制与源码均无旧地址 |
| 4 处补丁在位 | `verify_apk.py` 检查 `HS onLoad` / `DP ADDED` / `PRIVSRV v3 hotfix channel` / `BOOT v3` 标记 |
