## 1. 图片 / 资源链路（最容易误判，先讲清）

客户端 `gameEnv.fileCDN = "https://cysj-res.hortorgames.com/GameCreator-byte/"`（硬编码，未改）。
**这套域名不需要改**，因为自建服务端靠三层把它接管：

| 层 | 作用 |
|---|---|
| DNS 劫持（`dnssrv.py`/`dotsrv.py`） | 把 `*.hortorgames.com` 解析到自己的服务器 |
| 自签 CA + 手机信任 | 让 `https://cysj-res...` 的 TLS 能被客户端接受（证书 SAN 含 `*.hortorgames.com`） |
| nginx 443 SNI 分发 | `location /GameCreator-byte/ { alias /opt/privsrv/uploads/cover/; }` |

所以：
- `iconTextureName = 'demo1.png'`（**纯文件名**）→ 客户端拼 `fileCDN + 名字` → `demo1.png` 落到 `uploads/cover/demo1.png` → **实测 200 image/png**。
- 首页/发现页/我的作品/详情封面/Banner 全部走这条链路，图是通的。
- ⚠️ **`imgPath`/`iconTextureName` 必须是纯文件名**，不能带 `/uploads/cover/` 前缀，否则拼成两段路径 404。
- 头像特殊：客户端 `Util.isCdnPng(name)` 只认含 `pixel/` 的名字，`downLoadPng` 再拼 fileCDN；上传头像存到 `uploads/cover/pixel/`。

> **历史误判留档**：曾以为「V3 补丁只改了 urlRoot 没改 fileCDN → 所有图裂」。错。
> fileCDN 靠上面三层被接管，本来就通；盲目改 fileCDN 反而会改坏。

## 5. P2「实际可玩内容」的边界（诚实交底）

**为什么做不到真「能玩」**：

客户端点「开始游戏」的链路是：
```
GameCoverScene.onPlayBtn
  → if (!this.gamePackage) return;        // 没有工程包就直接返回，不会崩
  → downloadGamePack(url)                 // Util.downLoadBin：从 fileCDN 拉 .bin
  → bon.decode(pako.ungzip(bin))          // 解压解码成游戏工程对象
  → o.worldDatas[].worldLayout = unzip(layoutMin)   // 还原关卡布局
  → upgradeConf(tileConfs/actorConfs/deviceConfs/propConfs/weaponConfs/bulletConfs/…)
  → GameScene.play(工程对象)              // 引擎按配置搭世界
```
这个 `.bin` 是**原版编辑器导出的完整游戏工程**（bon 编码 + gzip，含关卡布局 + 全套物件配置），
不是能从服务端数据凭空拼出来的。本包不含、也无法构造这样的资源：
- 缺 `worldDatas`/`worldLayout` 的真实关卡布局；
- 缺 `tileConfs`/`actorConfs` 等配置的具体字段与取值；
- 客户端 `downloadGamePack` 里那一串 `upgradeConf` 对缺字段极敏感，造半个包只会白屏/崩溃。

**当前行为（安全降级）**：12 个 demo 游戏是**可浏览的展示项**——图标、名字、热度、封面、作者、
评论、置顶评论、点赞/收藏态、排行榜都能正常显示；点「开始游戏」因无 `gamePackage` 会安全返回，不崩。

**如果以后要支持真能玩**，需要：
1. 拿到（或自己用原版编辑器导出）合法的 `.bin` 工程包；
2. 放到 `uploads/cover/` 下（能被 fileCDN 命中）；
3. 让 `releaseGameData.gameDataCdnUrl` 指向它的文件名，并保证 `GameCoverScene` 拿到 `gamePackage`；
4. 逐项验证 `upgradeConf` 不缺字段（用真机，静态扫不出来）。
这一步属于「有资源才能做」，不是配置能补齐的，故本次不做，也不假装做了。

## 9. 逐界面排查（2026-11-19 第二轮，源码+服务端数据法）

### 排查方法
1. 从 `index.e248a.js` 的 `cc._RF.push` 提取 645 个真实组件模块：28 Scene / 19 Page / 146 Panel。
2. 提取客户端 `loadOne(key)` 请求的动态配置 key，比对服务端 `config_for_id` + `dynamicConfig`。
